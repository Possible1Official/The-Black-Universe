# Local crew behavior

Vega patrols the bridge and Ion patrols engineering using two hand-authored waypoints per officer. These are deterministic local state machines, not LLM agents, a navigation mesh, or general-purpose AI. Ion also has a containment-watch duty using a small engineering-only waypoint graph.

Each officer has a Rapier kinematic capsule and character controller. Waypoint commands are checked against physical ship geometry and the player's capsule. Officers turn in place before walking, pause at endpoints, and stop/face a visible visitor within 1.8 meters. Eye-to-eye sight uses the collision world; personal-space yielding within 0.75 meters still works without sight. Once attending, they resume patrol after the visitor moves beyond 2.2 meters; this prevents rapid stop/start chatter. A conversation holds movement and turns the speaking officer toward the player.

Sustained lack of forward progress for two simulation seconds reverses the local route after a short wait. This handles a local blockage; it does not find an arbitrary route around obstacles. Walking animation advances from actual distance traveled, with a blend to captured idle. Both officers use one bundled Mixamo Ely skin with independently cloned skeletons/mixers. The 1.313-meter source stride drives cycle time; exported ground-plane root drift is removed while vertical bob remains. Idle advances in simulation time, and both clips pause with physics during menu/dialogue/surface suspension. Procedural androids with simple arm/leg swings remain a loading-failure fallback. There is no IK, facial animation, run clip or unique appearance per officer. See ASSETS.md for provenance and budgets.

Simulation runs at the game's existing fixed 60 Hz step. The existing frame-time cap can slow simulation under very low rendering rates; no real-device performance claim is made. Crew behavior is transient and resets when loading the game; saved mission progression now uses v2 with legacy v1 migration (see POWER.md).

Tests: `tests/patrol.test.ts` covers bounded routes and endpoint waits, player attention, resumption, obstruction recovery, turn-rate/angle wrapping and attention hysteresis. `scripts/browser-qa.mjs` exercises rendered patrol displacement, yielding, solid body contact, crew dialogue and access-console collision alongside the original mission and mobile checks. Headless pointer lock is emulated; touch movement is dispatched in a mobile browser context.


## Containment watch

When containment trips, Ion temporarily prioritizes a diagnostics watch over the normal patrol. An authored three-node engineering graph joins the patrol start, a clearance junction and a safe standing point beside diagnostics. Breadth-first routing chooses the shortest edge path from the nearest authored node. The same Rapier capsule/controller checks every movement; the officer turns before walking, walks at 0.65 m/s, and uses actual travel to animate. On arrival, Ion stops and faces diagnostics while the trip stays latched. This is observation/guidance, not an automatic repair: the player must still cool and reset containment.

Nearby visitors and conversations interrupt travel/watch without losing its path; leaving resumes the duty with the existing attention hysteresis. Two simulation seconds without forward progress cause a 0.4-second wait and a graph replan from the current position. There is no teleport or forced collider bypass. Reset starts a return leg through the clearance junction before the original patrol goal resumes, avoiding a direct return across the relay console. A new trip during return reprioritizes watch. Pause/dialogue/surface transfer suspend physical crew motion as before. Task state is transient and recomputed from restored power state after reload.

This graph covers Ion's current engineering patrol and diagnostics only. It does not route through doors, find arbitrary detours, perceive every obstacle, schedule ship-wide tasks, diagnose real faults or plan with an LLM. Replanning may retry a persistently blocked edge; visitor yielding uses collision-based sight plus a personal-space fallback (see below). The task shares the new local Mixamo character and clips; it adds no separate asset, dependency or save field.

`tests/crew-duty.test.ts` covers trip/return/retrip priorities, station holding, attention/conversation interruption, bounded obstruction retry, immutable patrol input and actual Rapier traversal around both console colliders. With the dev server running, `node scripts/crew-duty-qa.mjs .local/qa/crew-duty.json .local/qa/crew-duty.png` installs an isolated tripped fixture, waits for physical arrival/holding, talks to Ion, resets containment through the real diagnostics UI and verifies return to patrol. Dev pose hooks only position the visitor; the officer's navigation is not teleported. Hardware FPS and real pointer lock remain unverified.


## Nearby awareness and interaction visibility

Crew sample eye-to-eye Rapier sight at most ten times per simulation second while the visitor is within 2.3 horizontal meters. Their own capsule and the visitor's capsule are excluded. A visible visitor starts attention within 1.8 meters and retains it until 2.2 meters; an occluded visitor no longer attracts patrol/watch attention. Personal space below 0.75 meters and an active conversation still stop the officer. A task's path remains intact while attending. This is omnidirectional nearby awareness, not a field-of-view cone, hearing, visual recognition, memory or LLM perception. The cache can delay a sight change by about 0.1 simulation second (slightly more from fixed-step rounding).

Interactions also require clear collision sight from the camera to the target anchor, after the existing 2.65-meter reach and view-cone tests. E/touch E recomputes selection instead of using a stale prompt. Player and intended target colliders are excluded; intervening walls, doors, consoles, rock colliders and other crew can block. The sample sphere and extraction pole remain usable because their own colliders are associated with their targets. Door sight follows actual collider position, not the requested open flag. Collision queries initialize before the first frame.

These checks use the physical approximation, not pixel visibility or render meshes: decorative non-colliding objects do not occlude, and collider approximations may block differently from visible details. A 3-centimeter endpoint margin avoids numerical hits at the anchor. They do not add renderer passes, geometry, textures, remote calls or save fields. Interaction ray checks add CPU query work; no measured FPS gain is claimed.

`tests/visibility.test.ts` exercises the reproduced wall/panel defect, moving doors, endpoint exclusions, an intervening body, surface anchors, blocked patrol/watch attention, personal space, speaking and visible hysteresis. `node scripts/visibility-qa.mjs .local/qa/visibility.json .local/qa/visibility-wall.png` reproduces the engineering-side wall pose, confirms E cannot open the bulkhead, then verifies the clear panel and a visible officer's conversation. Dev pose hooks establish visitor positions; real E performs interactions.
